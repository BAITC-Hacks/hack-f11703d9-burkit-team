# Burkit — backend-каркас для кейса AI Sana

Это рабочий каркас backend-части MVP. Сейчас в нём есть FastAPI, SQLite,
эндпоинты задач и откликов, а также тестовая генерация уточняющих вопросов.

Что уже работает:

- создание и просмотр задач;
- изменение карточки задачи;
- публикация и закрытие задачи;
- каталог открытых задач;
- создание и просмотр откликов;
- ручной выбор или отклонение отклика;
- тестовый AI-режим с тремя уточняющими вопросами;
- понятные сообщения об ошибках на русском языке.

Чего пока нет:

- подключения к реальному OpenAI API;
- авторизации и проверки владельца задачи;
- Pydantic-схем запросов и ответов;
- production-настроек и миграций базы данных.

## Запуск

Активировать созданное виртуальное окружение:

```powershell
.venv\Scripts\Activate.ps1
```

Запустить сервер:

```powershell
uvicorn backend.main:app --reload
```

После запуска доступны:

- API: <http://127.0.0.1:8000>
- Swagger: <http://127.0.0.1:8000/docs>
- проверка работы: <http://127.0.0.1:8000/api/health>

База создаётся автоматически в `backend/data/app.db` и не добавляется в Git.

## Основной сценарий API

1. `POST /api/tasks` — создать черновик.
2. `POST /api/tasks/{id}/questions` — получить тестовые вопросы.
3. `PATCH /api/tasks/{id}` — заполнить карточку.
4. `POST /api/tasks/{id}/publish` — открыть задачу для откликов.
5. `GET /api/tasks?status=open` — получить каталог.
6. `POST /api/tasks/{id}/proposals` — отправить отклик.
7. `GET /api/tasks/{id}/proposals` — получить отклики.
8. `PATCH /api/proposals/{id}/decision` — выбрать или отклонить отклик.
9. `POST /api/tasks/{id}/close` — закрыть задачу для новых откликов.

Статус `draft` означает, что карточка ещё не опубликована. Статус `open`
означает, что задача опубликована и принимает отклики. Статус `closed`
означает, что карточка остаётся доступной для просмотра, но новые отклики
больше не принимаются.

После создания и каждого изменения карточки backend пересчитывает рейтинг,
сохраняет `readiness_score` и возвращает объект `rating` с уровнем готовности
и подсказками по недостающим полям.

## AI-режим

Сейчас используется только `mock`: сервер возвращает заранее заданные вопросы
в нужном формате. Это позволяет проверить соединение frontend, backend и базы
до получения API-ключа.

Если задать `AI_MODE=disabled`, AI-эндпоинт вернёт ошибку `503`, а остальные
эндпоинты продолжат работать.
