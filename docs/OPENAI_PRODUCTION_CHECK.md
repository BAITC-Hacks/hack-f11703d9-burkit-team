# Проверка OpenAI в production

Production использует серверные переменные Vercel. Значение API-ключа нельзя
добавлять в `.env.example`, frontend, GitHub issue, логи или командную строку.

## Настройка Vercel

В разделе **Project → Settings → Environment Variables** для окружения
**Production** должны быть заданы:

| Переменная | Значение | Тип |
| --- | --- | --- |
| `OPENAI_API_KEY` | ключ проекта OpenAI | Sensitive |
| `AI_MODE` | `openai` | Config |
| `OPENAI_MODEL` | `gpt-5-mini` | Config |
| `OPENAI_TIMEOUT_SECONDS` | `20` | Config |

После изменения переменных нужен новый deployment: существующий deployment не
получит новые значения автоматически.

## Автоматическая проверка

После production-деплоя выполнить из корня репозитория:

```powershell
python scripts/verify_openai_production.py https://hack-f11703d9-burkit-team.vercel.app
```

Скрипт выполняет следующий сценарий:

1. Проверяет, что `/api/health` сообщает `ai_mode=openai` и `ai_ready=true`.
2. Создаёт по одному русскому, казахскому и английскому черновику.
3. Запрашивает реальные вопросы и требует `provider=openai`.
4. Проверяет количество вопросов, уникальность и допустимость `field`, а также
   непустой `text`.
5. Повторно читает каждую задачу и подтверждает, что черновик сохранился.
6. Выводит вопросы для содержательной проверки человеком.

Проверочные записи остаются черновиками с автором `Production smoke test ...`.
Это позволяет увидеть в базе те же данные, на которых был получен отчёт.

## Проверка ошибок

Автотесты покрывают таймаут OpenAI, отсутствие ключа, отключённый режим,
некорректный JSON, неверную структуру и повтор запроса после ошибки. Во всех
случаях ключ не возвращается клиенту, а ранее созданный черновик остаётся в БД.
